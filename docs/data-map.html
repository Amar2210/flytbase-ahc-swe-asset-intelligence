The main relationships

This overview shows the main paths. The Mermaid files include the full relationship and field maps.

Stored ID or file pathDocument code or textNested structure shown in field browser
  • Areas + teams + users → well ownership through their ID fields.
  • Wells → inspections, maintenance, regulatory events and notes through asset_id.
  • Inspections ← repair triggers, correction targets and regulatory events through inspection IDs.
  • Maintenance → Markdown reports through report_file.
  • Well type → manual by code; protocol ID → section within an SOP.

No single field links everything. asset_id belongs to well records. Fleet users, teams, manuals and SOPs have their own identifiers. These source structures are not existing SQL tables.

Which field makes the connection?

LinkWhat it connects
asset_idWell metadata ↔ inspections, maintenance, regulatory events and context notes. Area membership also lists asset_ids[].
user_idTeam leads, well owners, inspectors, technicians and note authors ↔ fleet users. These are different role-specific field names.
inspection_idLatest inspection summary, maintenance trigger, regulatory spill discovery and correction target ↔ one inspection.
area_id / team_idWell ↔ geographic area and owning team; user ↔ team; area ↔ production team.
asset_id + equipment_kindMaintenance equipment ↔ the matching equipment[].kind within that well. Maintenance does not carry equipment_id.
report_fileMaintenance ↔ a report path relative to the well folder. Follow the stored path; two report names differ from their maintenance IDs.
well_typeWell ↔ fleet/well-types/{well_type}.md. This is a code-to-document convention.
protocol_idRegulatory event ↔ a named protocol in an SOP. Report text mentions several protocols; no report-to-protocol table is supplied.

Geography and ownership in the actual data

Four areas contain 50 wells each. Coordinates are embedded in area.center and well.location. No separate geography file or polygon boundary is supplied.

Field Maintenance (TEAM-MX, 5 users) and HSE (TEAM-HSE, 2 users) support the field. Areas belong to the two production teams.

All 15 users and their teams

Membership comes from users.team_id. The lead marker comes from teams.lead_user_id. A role describes the person; source data does not define an authorization policy.
