SQL, RAG, and graphs solve different problems

Recommended foundation

SQL database

Store structured records and connect them through identifiers. Filter dates, count inspections, and calculate rankings over all relevant rows.

Well→InspectionandRepair

These links are ordinary foreign keys. SQL joins can follow them.

Recommended retrieval method

RAG

Retrieval-augmented generation gives the model selected evidence before it answers. Retrieve SQL results and relevant document sections.

Example: fetch a well’s inspections, retrieve its temperature rule, then explain the result with citations. Start with identifier and text search; add embeddings if needed.

Optional later

Graph database

Store entities and relationships for traversal. Consider this when questions depend on complex paths across many kinds of relationships.

The known well, inspection, and repair links do not yet justify a second database. Revisit if relationship queries become difficult to express in SQL.

Upload the evaluation data

  1. Stage the ZIP. Keep existing datasets while the new upload is checked.
  2. Validate the package. Check expected files, columns, identifiers, dates, and links between records.
  3. Show the result. Display dataset version, row counts, date range, and validation errors.
  4. Register the validated version. Keep both sample and test imports available, with versioned source citations.

A local folder option can call the same importer. The challenge requires test data alongside sample data. Whether to merge a verified continuation or select separate versions, and how to carry notes forward, remain open.

Keep these choices explicit

Local demo Chosen

Use SQLite for one demo instance with persistent local storage. Reconsider PostgreSQL if later hosting loses local files or runs multiple app instances.

Time and evaluation Proposed

Set one timezone per field. Show an explicit as_of date for evaluation. Operators need no timezone selector in each message.

Chat correction authority Pending review

Imported correction records already have defined effects. The user will review who can create new formal corrections from chat and how conflicts are resolved.

Worked example / time matters

A crew member reports: “WELL-0001 is under emergency maintenance through 20 October.” The system stores the reported window and the original message.

On 21 October: “The reported maintenance window ended on 20 October. No newer update confirms completion or a return to production.”

Official references and limits

  • Streamlit chat elements support messages with tables and charts. Session State belongs to a user session and resets when its WebSocket connection is replaced.
  • SQLite: appropriate uses describes local application storage and demo use, plus cases where a client/server database fits better. The deployment recommendation above applies that guidance to this project.
  • Challenge dataset repository is the source for domain rules. This page proposes architecture; it does not replace those rules.
