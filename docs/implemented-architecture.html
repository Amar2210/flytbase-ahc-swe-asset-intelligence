Python saves your prompt, then retains up to 16 stored messages within a combined 12,000-character history budget, prioritizing newer messages and marking omissions. The current user prompt stays intact up to the 20,000-character input limit, even if it alone exceeds that character budget. Every model call resends retained context plus bounded tool exchanges. Older saved chats remain searchable by date. The evidence panel lists tool sources, not the full prompt or private history.
Document, output and prompt limits

Document search returns five matches by default, with a maximum of ten. Each excerpt covers up to 21 lines and 10,000 characters. get_document returns up to 40,000 characters before model-bound strings are clipped to 6,000. Other lists are capped at 20 items. Valid-JSON tool responses then share a 24,000-character budget with a 12,000-character per-tool maximum. Omitted evidence is marked; full rows and source metadata remain in the UI. The revised full system context measured 1,690 Google tokens, down from 2,304 (26.65%). The input guard is per request, not a live TPM meter or pacing mechanism; unavailable counts still permit generation.

Requested through instructions

Evidence coverage and metric choice

Gemma is told to use effective views, read applicable SOPs, fetch fresh crew notes, and calculate seven days per nonproducing inspection.

There is no mandatory SOP gate, complete note-coverage check, or SQL semantic validator. A source reference does not prove the full SOP text reached Gemma.

A proposed improvement is to require applicable notes and rule passages before a final answer. That gate is not implemented.

The false-spill SOP has a specific effect. Section 7 excludes detections confirmed as water, mud, or shadow by a qualified person. The backend supports this effect through correction overlays. A new correction still needs review. The app does not independently verify the person's qualification.
Known citation gap in general SQL. SQL access to well_types attaches production-threshold manuals, even for spill-only queries. These references do not justify spill counts. The T350 reference starts on blank line 23 before the rule on lines 24–26. The spill SOP is not automatically retrieved through this SQL mechanism. The targeted containment tool separately retrieves its SR-02 rule and linked report passages; general source relevance and mandatory SOP coverage remain unresolved.

Bounded recovery

  • Transient inference failures use at most three HTTP attempts within the request timeout.
  • Quota and invalid-key failures are not automatically retried.
  • If synthesis fails after a read, the app shows returned facts and sources as a partial response.
  • After a transient error or HTTP 429 before a read, an explicit well ID can trigger a local lookup. That path never saves a crew report or retries the quota-blocked API.

Earlier Google checks returned HTTP 500; OpenRouter free routes returned upstream HTTP 429. Before the latest changes, the Southwest Block 24 question grew to 18,862 input tokens and its third call timed out. After the three-call cap, compact context and containment tool were added, the exact question completed in two Google calls: 3,109 then 7,197 input tokens, one generation HTTP attempt each, in 73.3 seconds. It correctly returned WELL-0082 at 7.1 hours and WELL-0100 at 8.1 hours against SR-02's four-hour deadline. This public-data check verifies that question, not all challenge scenarios or continuous provider availability.

Measure the complete input and preview visuals

The chat now shows the latest input tokens, peak context and model-call count. Google counts the actual complete request: system instructions, schema, history, tool definitions, tool results and any retrieved SOP text. Counts appear before generation and persist afterward, including errors. Returned usageMetadata.promptTokenCount supersedes preflight when provided; missing values remain unavailable. Peak context is the largest single input window, rather than the sum of repeated calls.

The counter adds one full-payload countTokens.generateContentRequest tokenization request per Google model round, without repeating it for inference retries. Per-call counters distinguish model rounds, tokenization requests and inference HTTP attempts. Preflight counts do not establish billed usage. A new Visual preview tab reads actual SQLite records through preset queries without model calls or chat writes. It provides status cards, trends, downtime bars, corrected-spill heatmaps, maps and tables.

Historical OpenRouter metadata showed 0 of 50 daily free requests used, with 50 remaining; upstream 429 errors did not establish daily exhaustion. The active Google route has since completed a real two-round heatmap response.
